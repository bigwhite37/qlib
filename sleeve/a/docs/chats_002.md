
## 一、需求不变：先冻结验收合同

沿用上一版已经量化的标准，不通过修改指标定义宣布成功。

| 项目     | V2验收口径                                  |
| ------ | --------------------------------------- |
| 投资范围   | 数据实际覆盖的历史A股全市场个股，不改成固定指数成分股策略           |
| 数据     | 仅现有Qlib日频数据，2015-01-05至2026-09-14       |
| 交易时序   | T日收盘后决策，T+1日收盘尝试成交                      |
| 方向     | 只做多、不加杠杆；允许现金和低仓位                       |
| 收益     | **扣费后的账户复合年化收益≥25%**，不是持仓股票收益或超额收益      |
| 波动     | 年化波动率≤10%                               |
| 回撤     | 最大回撤≤10%，争取≤8%                          |
| 胜率     | **完整交易回合扣费后胜率≥70%**                     |
| 稳定性    | 每个完整自然季度账户净收益为正，单独逐季检查                  |
| 有效持仓日  | 实际股票市值占净资产≥20%，并且实际持有≥3只股票              |
| 最低持仓频率 | 任意完整滚动252日，有效持仓日占比≥60%；任意完整滚动63日，占比≥40% |

其中10%波动、10%回撤和持仓频率的具体数值，是上一版为了操作化需求提出的。本轮保留，避免评审过程中移动标准。

**高胜率、正季度收益和最低频率都不能通过会计处理实现。** 分批卖出不能拆成多个盈利回合；未平仓亏损必须计入净值；空仓季度的零收益不能算正收益。

这些是联合验收条件，不是未来收益保证。

## 二、对旧设计的review：保留什么，替换什么

| 旧设计                             | Review结论                        | V2处理                           |
| ------------------------------- | ------------------------------- | ------------------------------ |
| 趋势、相对强势、回撤幅度、修复确认等条件全部满足才买      | 将收益来源过早限定为一种狭窄形态，尚无证据说明它能提供足够机会 | **改成特征，不再全部作为硬门槛**             |
| 用10日上涨标签辅助筛选，但实际存在止损、跟踪退出、20日退出 | 模型学习的结果与实际交易政策明显不一致             | **按实际单股退出政策生成训练标签**            |
| 将低波股票作为重要偏好，再做组合波动限制            | 可能重复限制风险，但不能未经检验就认定低波偏好有害       | 波动保留为模型特征；账户风险主要在组合层控制         |
| 市场限制、波动限制、历史回撤限制同时生效            | 可能形成长期低仓位；历史回撤限制缺少清楚的恢复语义       | 保留市场与波动上限，删除旧版静态回撤降仓链          |
| 20日到期退出                         | 本身不一定错误，不能凭叙事认定它“砍掉主升浪”         | **首轮仍保留20日，但标签和执行必须一致**        |
| 机器学习只是规则策略的可选装饰                 | 没有直接对“赚钱多少”和“赚钱概率”建模            | 两个小模型成为主要选股依据                  |
| 只在最后检查持仓频率                      | 可能花大量时间优化一套天然机会不足的策略            | 在开发初期就检查“收益—胜率—覆盖率”是否存在同时达标的配置 |

**这次不是把规则全部放松，而是区分两种东西：数据与执行的硬约束必须严格；未经验证的选股偏好，交给训练和验证决定。**

## 三、新策略究竟赚什么钱

V2研究的是以下假设：

> **价量形态是否赚钱，取决于市场环境；同样的短期下跌，在健康市场中的相对强势股票上，和在普遍恶化的市场中，可能对应不同的后续交易结果。**

因此，不再预先规定“只有回撤修复能赚钱”，而是让同一组模型比较：

**趋势延续机会。** 一只股票没有出现旧版要求的1～3ATR回撤，但中期相对强势、成交活跃、价格结构健康，仍然可以入选。

**短期错位后的修复机会。** 一只股票近期弱于市场，但中期结构和市场环境没有同步恶化，也可以入选；不必先等待它站回5日均线。

**应当回避的相对强势。** 市场普遍下跌时，一只股票虽然排名靠前，但预计绝对收益仍为负，就不买。不能因为“比其他股票跌得少”便把它当成绝对收益机会。

这些不是三个子策略，也不需要新增资金分配器。**它们由同一组价量特征、市场特征和两个预测目标共同表达。**

这里的收益假设仍需验证。换成模型不会自动创造有效信号；它的优势在于，能直接检验和淘汰这些假设，而不是把它们写成不可质疑的筛选规则。

## 四、先固定交易政策，再生成模型标签

这是V2最重要的改动。**先定义一笔交易怎样结束，再预测它是否值得开始。**

### 4.1 成交时序保持不变

T日收盘后，冻结T+1日的买卖名单、委托数量和价格约束。

T+1日行情只能用于撮合、成交检查和结算，不能用于重新选股或反推委托股数。

第一组配置保留买入价格保护：

$$
P^{buy\_limit}_{T+1}=1.03\times P_T
$$

这里使用可核验的原始价格。T+1收盘超过该限价则不买；不能看到原订单失败后，再用当天收盘结果替换成另一只股票。

**保留3%不是因为它已经被证明最优，而是避免一次修改太多执行条件。** 后续应单独检查它拒绝了多少交易、拒绝交易的后续收益如何。

### 4.2 单股退出政策

设实际入场日为 \(e=T+1\)，入场时冻结相对止损距离：

$$
s_i=
\operatorname{clip}
\left(
2\frac{ATR_{20,i,T}}{C_{i,T}},
4\%,8\%
\right)
$$

首轮使用以下政策：

| 类型     | 触发条件                                          | 执行方式                  |
| ------ | --------------------------------------------- | --------------------- |
| 止损     | 收盘相对入场价跌幅达到 \(s_i\)                           | 下一交易日收盘尝试卖出           |
| 盈利保护   | 最高收盘浮盈达到 \(1.5s_i\) 后，启用距离最高收盘价 \(s_i\) 的跟踪退出 | 收盘触发，下一交易日收盘尝试卖出      |
| 时间退出   | 入场后持有20个交易日收益区间                               | 事先安排在 \(e+20\) 收盘尝试卖出 |
| 市场极端风险 | 触发后文的极端风险状态                                   | 下一交易日收盘尝试卖出           |

**不设置小幅盈利就固定落袋的止盈，不要求重新站上均线才入场，也不因模型排名每天变化而频繁换股。**

首轮保留20日上限，原因不是“趋势只能持续20天”，而是给训练结果一个明确、可审计的交易政策。是否延长持有期，应通过交易结果随持有时间的变化来判断，而不是凭想象改成40或60日。

止损、跟踪退出全部按收盘触发。不能根据当天最低价触及止损，就假设在当天止损价成交。

遇到无法卖出，保持待退出状态继续尝试，实际持有时间可以超过20日。**20日是计划退出期限，不是强制虚构成交的期限。**

### 4.3 标签不再使用简单的固定10日涨跌

对每个历史信号日、每只当时可选股票，模拟：

> T+1日按约定尝试买入；成交后执行上述退出政策；记录最终交易结果。

得到两个标签：

$$
Y^{return}_{i,T}=R^{policy,net}_{i,T}
$$

$$
Y^{win}_{i,T}
=
\mathbf 1\!\left(R^{policy,net}_{i,T}>0\right)
$$

即：

**收益模型学“按这套政策交易，平均能赚多少”。**

**胜率模型学“按这套政策交易，扣费后盈利的概率”。**

标签生成器与回测策略共用同一个 `ExitPolicy`，不能各写一份相似但不完全相同的退出逻辑。

### 4.4 必须处理的标签边界

未成交订单不是亏损交易，也不是零收益的已成交交易，要单独记录。模型输出应解释为“在按约定成交的条件下”的交易结果预测，最终机会覆盖率仍按实际成交计算。

费用标签可以先按固定参考单笔金额，例如1万元，逐笔计算；实际组合按实际委托金额重新核算费用，并记录参考费用与实际费用的差异。**不能把参考金额下的预测概率直接当作小额订单的真实胜率。**

停牌、退出受阻、数据截止尚未平仓的样本，需要保留未成熟或未闭合标记。尤其不能把退市或长期无法退出的坏样本简单删除后，仍声称胜率没有偏差。

此外，组合主动降仓可能使实际退出早于单股政策。这个差异要单列分析，**单股模型预测的盈利概率仍不等于最终账户的完整交易胜率。**

## 五、选股模型与每天的具体买入规则

### 5.1 股票池只做必要过滤

使用历史 `all` 股票池及其有效日期，保留以下基础约束：有至少120个有效历史观测；最近20日至少18日有有效行情；原始价格≥3元；流动性不处于当日市场最差20%；必需价格、成交量和复权字段可用。

**取消旧版“波动率必须低于70%分位数”“RS60必须前30%”“必须站上多条均线”等硬门槛。**

全市场是研究范围，不代表每天必须允许买所有股票。但缺少某个板块数据时，要报告覆盖缺口，不能静默改成另一个市场范围。

Qlib将股票池定义为证券名单及其日期区间；其价格和成交量采用调整口径，官方说明可通过 `$close / $factor` 恢复原始收盘价。因此，股票池历史范围与原始价格过滤都必须核验，不能仅凭配置中的 `all` 或 `$close` 名称判断。([Qlib Documentation][1])

### 5.2 特征：以Alpha158为主体，补少量市场信息

个股特征主要复用Alpha158，额外补充相对市场20日、60日收益，以及过去5日剔除市场影响后的收益。

市场特征使用后文定义的市场20日、60日收益、20日和60日均线上方股票占比、短期市场宽度变化、下跌扩散比例。

这能让模型学习“相同个股形态在不同市场中的含义”，而不是只能在选股完成后机械减仓。

当前Alpha158默认包含VWAP相关特征；数据没有VWAP时要移除对应特征，不能填零假装存在。

**市场特征不能做当日横截面标准化。** 同一天所有股票的市场特征相同，横截面标准化会把这些信息消掉。

### 5.3 两个Qlib自带模型即可

分别训练：

```text
return_model：LGBModel(loss="mse")
win_model：   LGBModel(loss="binary")
```

它们共享特征缓存，但使用各自的单列标签。当前Qlib的 `LGBModel` 支持这两种目标，其训练接口不接受同时传入多列标签，因此应使用两个实例，而不是拼成一个多标签任务。

首轮固定小模型参数：`num_leaves=15`、`max_depth=4`、`learning_rate=0.03`、`min_data_in_leaf=500`，最多500轮、50轮早停，固定随机种子。先不搜索模型结构，不做深度模型或复杂集成。

**两个标签都不做横截面标准化。** 我们要预测绝对净收益和0/1盈利结果。Alpha158默认学习处理包含标签横截面标准化，必须显式取消，否则目标语义已经改变。

盈利概率还要在独立时间区间校准，例如使用sigmoid校准，并检查预测概率分桶与实际命中率。校准数据不能与模型拟合数据混用，也不使用默认随机交叉验证打散时间。([scikit-learn][2])

### 5.4 每天怎样买

第一组固定配置：

$$
\widehat{R}^{net}_{i,T}\ge1\%
$$

$$
\widehat{P}^{calibrated}_{i,T}\ge70\%
$$

通过两项门槛后，**按预期净收益从高到低排序**，在仓位和现金允许时建仓。

例如，预期净收益5%但盈利概率只有45%的股票，不符合高胜率目标；盈利概率85%但预期净收益只有0.1%的股票，也不值得为了凑胜率而买。

这里不再把收益预测乘以盈利概率：如果收益模型已经预测包含亏损结果的平均净收益，再乘一次盈利概率会混淆目标。

具体持仓规则如下：

| 项目       | V2首轮配置                     |
| -------- | -------------------------- |
| 最大持股数    | 12只                        |
| 单股目标仓位上限 | 净资产的8%                     |
| 每日新增     | 最多3只                       |
| 已有持仓     | 按退出政策持有，不因每日排名变化而反复换仓      |
| 加仓       | 不因下跌而摊低成本；首轮不对存量持仓机械补回目标权重 |
| 空缺       | 没有合格候选则留现金，并计入频率是否违规       |

**预测概率70%不是实际胜率70%的保证。** 最终仍以完整交易回合验收。模型若只能在极少数日期产生合格候选，V2同样不合格，不能靠模型名称掩盖机会不足。

## 六、市场强弱与仓位：减少重复限制，但不放松风险目标

### 6.1 市场指标

使用前一日确定的基础股票池，计算当日等权市场收益并形成市场代理序列 \(M_t\)。它用于状态识别，不把它冒充一个没有成本的可投资指数。

另外计算：

$$
B_{20,t}=\text{收盘高于20日均线的股票比例}
$$

$$
B_{60,t}=\text{收盘高于60日均线的股票比例}
$$

$$
Q_t=\text{当日跌幅超过3%的股票比例}
$$

所有指标只使用截至信号日的信息；缺失样本比例需要同步监控。

### 6.2 市场仓位上限

按以下优先级判断：

| 市场状态  | 首轮定义                                        | 股票总仓位上限 |
| ----- | ------------------------------------------- | ------: |
| 极端风险  | 市场代理5日收益≤−6%；或 \(B_{60}<20\%\) 且 \(Q>35\%\) |      0% |
| 强势    | 市场60日收益>0，且 \(B_{60}\ge55\%\)               |     90% |
| 中性或修复 | 不属于极端风险、强势，且市场20日收益>0或 \(B_{60}\ge40\%\)    |     70% |
| 弱势    | 其余情况                                        |     35% |

相比旧版，**不再要求弱势市场的每一笔买入额外通过一组“修复确认”条件**。市场状态已进入模型，个股还必须通过绝对净收益和盈利概率门槛，弱市再由35%仓位上限约束风险。

### 6.3 空仓后的恢复规则必须明确

极端风险解除后，要求连续两个信号日同时满足：不再触发极端风险、市场最近3日收益为正、\(B_{20}\) 高于5日前。

满足后恢复至35%上限；再连续3个信号日保持非极端状态，回到正常状态表。

**恢复不依赖账户先回到历史最高净值。** 全现金净值不会靠市场反弹自行修复，不能用一个无法自发满足的条件锁住账户。

### 6.4 组合波动只统一限制一次

根据拟持有组合及现持仓的历史收益，估计满仓组合年化波动 \(\widehat{\sigma}_{basket}\)：

$$
g^{vol}_t
=
\min\left(1,\frac{10\%}{\widehat{\sigma}_{basket,t}}\right)
$$

最终总仓位：

$$
g_t^{target}
=
\min\left(
g_t^{market},
g_t^{vol},
90\%
\right)
$$

**不是先乘市场系数，再乘波动系数，再乘历史回撤系数。**

初步采用过去60日收益的收缩协方差估计。组合权重先接近等权，再施加单股上限与总风险限制，不再把低波偏好叠加成多层独立评分。

删除旧版“历史回撤达到4%和6%后持续压仓”的机制，但**最大回撤≤10%的验收要求不变**。删除某个运行机制，不等于放松最终风险标准；若新机制不能控制回撤，仍判定不合格。

由于成交延迟和价格跳变，预测10%波动也不等于实际波动必然≤10%，必须实测。

## 七、最低持仓频率：从开发初期就检查，不能最后才发现长期空仓

继续按实际持仓定义：

$$
I_t=
\mathbf1\left(
\text{股票仓位}_t\ge20\%
\;\land\;
\text{实际持股数}_t\ge3
\right)
$$

检查滚动252日和63日的有效持仓比例，门槛分别保持60%和40%。

与旧版不同，开发第一阶段就要输出一张**机会覆盖表**：

| 每日统计              | 用途              |
| ----------------- | --------------- |
| 基础可选股票数           | 判断数据或股票池是否异常    |
| 预期净收益合格数          | 判断是否根本没有足够预期收益  |
| 盈利概率合格数           | 判断高胜率约束是否导致机会过少 |
| 两项同时合格数           | 判断策略可交易机会是否充足   |
| 计划买入、实际成交数        | 区分信号不足和执行失败     |
| 市场、波动、现金分别限制了多少仓位 | 判断低仓位来源         |
| 实际有效持仓日           | 直接计算频率验收        |

尤其注意：**预测文件断档、全部NaN、信号日期错位，不能被系统解释成“模型建议长期空仓”。**

频率不足时，正确动作是判定该配置不可行、查明缺口来自哪里，而不是临时降低买入标准凑数。开发阶段可以比较不同入场阈值，但只有实际胜率、收益、风险和频率同时通过的配置才能保留。

## 八、数据区间重新划分：已看过的数据不能重新包装成盲测

你已经用历史回测发现旧版失败，所以新版必须区分：

**模型没有用来拟合的数据**，和**研究人员从未看过结果的数据**。

前者仍可做滚动预测检验；后者才是严格意义上的未接触验证。不能把已经看过的年份重新切一遍，就恢复它的独立性。

### 8.1 各区间用途

| 数据区间                      | V2用途                               |
| ------------------------- | ---------------------------------- |
| **2015-01-05～2015-12-31** | 数据审计、指标预热；历史充足后的部分保留压力回放           |
| **2016-01-01～2019-12-31** | 策略政策、标签生成、模型管线开发                   |
| **2020-01-01～2022-12-31** | 主要滚动验证与少量参数选择                      |
| **2023-01-01～2024-12-31** | 版本复核；未接触过的部分才可称封存验证                |
| **2025-01-01～2026-09-14** | 最近阶段连续回放、执行敏感性和稳定性复核；已查看部分不得再称全新盲测 |
| **V2冻结后的新增数据**            | 真正前瞻验证；最早可从2026-09-15起纳入新增记录       |

这些区间仍然有价值。**历史被看过，不代表不能研究；只是证据强度不能夸大。**

2026年第三季度尚未结束，不能把截至9月14日的结果当完整季度。9月14日特征形成的次日订单，也不能虚构为现有行情范围内已完成的交易。

### 8.2 每个季度如何训练

采用固定自然季度更新：

> **此前36个月训练＋此前6个月早停验证＋此前6个月概率校准，预测接下来一个季度。**

例如：

| 预测季度      | 模型训练            | 早停验证     | 概率校准     |
| --------- | --------------- | -------- | -------- |
| 2020年第一季度 | 2016—2018年      | 2019年上半年 | 2019年下半年 |
| 2026年第三季度 | 2022-07～2025-06 | 2025年下半年 | 2026年上半年 |

日期按Qlib交易日历映射。季度内不因近期亏损改变参数；后续季度可以按冻结协议使用已经成熟的数据重新训练。

两个模型共享相同时间划分。校准数据不能再参与树模型拟合；概率阈值的策略选择主要在2020—2022滚动验证中完成，而不是不断查看最近区间后微调。

### 8.3 标签隔离不能只写一个固定天数

正常20日交易政策，标签最远至少使用到 \(T+21\) 的价格；无法退出时可能更晚。

每个样本保存：

```text
signal_time
entry_time
exit_signal_time
exit_fill_time
label_end_time
label_status
```

每个训练、早停、校准边界都必须检查：

$$
label\_end\_time<下一阶段的起点
$$

不能只用“信号日期属于训练区间”作为合法条件。

Qlib的 `RollingGen` 有滚动和截断能力，但其截断逻辑围绕测试起点处理；它不能自动保证这里新增的训练—早停—校准三层边界都符合交易标签的实际成熟时间。应复用任务结构，再补显式边界检查。

最后拼接的是连续预测信号，**不是每季度重置本金后的收益曲线**。持仓、现金、回撤和待成交订单都必须跨季度延续。

## 九、Qlib实现：不用重建框架，但有几个地方必须覆盖

### 9.1 组件映射

| 功能    | 复用Qlib                                             | 自定义部分               |
| ----- | -------------------------------------------------- | ------------------- |
| 数据与特征 | `D.features`、`QlibDataLoader`、Alpha158特征族          | 市场聚合、数据资格审计         |
| 数据集   | `DataHandlerLP`、`DatasetH`                         | 两种交易政策标签、时间隔离       |
| 模型    | 两个 `LGBModel`                                      | 概率校准与预测合并           |
| 策略    | `WeightStrategyBase`                               | 选股、固定退出政策、仓位目标      |
| 下单与执行 | `OrderGenerator`扩展点、`Exchange`、`SimulatorExecutor` | 严格事前定数量、价格保护、实际交易限制 |
| 实验记录  | `R`、`SignalRecord`、`PortAnaRecord`                 | 交易回合、频率和因果审计指标      |

`WeightStrategyBase` 已有从目标权重到订单生成的连接，适合复用，不必从头写账户与回测引擎。

### 9.2 优先防住两个实现错误

**第一，缺少预测时仍然要执行退出检查。**

当前 `WeightStrategyBase` 在 `pred_score is None` 时会直接返回空交易决策。若直接把它套在有独立止损和市场退出逻辑的策略上，必须覆盖这个行为：没有预测只能阻止新买入，不能跳过已持仓的风险检查。

**第二，订单生成不能偷看成交日。**

当前 `OrderGenWOInteract` 虽主要用预测日价格估算股数，但仍查询成交日可交易状态。V2应把这部分未来状态检查移到执行层；策略层只提交事前确定的订单。

买单现金预算不预支同一收盘撮合中尚未完成的卖出资金。成交不足、费用超预算、交易单位约束都要真实保留，不能事后重新分配到更好的股票上。

### 9.3 日线无法提供的精度，不要假装已经解决

仅有日线，无法确认收盘时的全部排队和流动性。成交量上限只能做容量约束，不能证明该收盘订单一定能成交。

历史风险警示身份、特殊交易状态、退市终值等若缺失，要报告不确定性，并做更保守的撮合和估值敏感性检查。**不能用一个统一涨跌幅阈值，就声称准确重建了整个历史全市场。**

这些限制不能用来解释所有收益差，但也不能为了让新版赚钱而删除。

## 十、怎么验证优化有效：先验证收益来源，再验证完整约束

不要一上来只看V2最终年化。至少保留下面四组连续账户实验：

| 实验 | 设置                        | 回答的问题                  |
| -- | ------------------------- | ---------------------- |
| A  | 收益模型排序，固定仓位，使用同一退出政策与严格费用 | 收益模型本身是否有选股价值？         |
| B  | A＋盈利概率筛选                  | 高胜率筛选改善了什么，又牺牲多少机会和收益？ |
| C  | B＋市场状态仓位上限                | 市场判断是否有增益，而不是只减少参与？    |
| D  | C＋组合波动限制                  | 完整V2能否满足全部要求？          |

四组都不能使用更乐观的成交方式。固定仓位实验只是归因基线，不是放松最终风险要求。

**如果A在滚动验证中都没有明显的扣费收益优势，就不应该继续给D增加风控参数。** 应回到标签、特征与模型，检查是否存在可利用的收益信号。

### 首轮参数搜索范围

先固定股票池、退出政策、市场状态和模型结构，只比较9组入场参数：

$$
p_{\min}\in\{0.65,0.70,0.75\}
$$

$$
\mu_{\min}\in\{0.5\%,1.0\%,1.5\%\}
$$

默认中心配置为70%与1%。

这里搜索的是**模型输出阈值**，不是把实际胜率目标改成65%。任何候选配置仍必须达到完整交易实际胜率≥70%，同时达到持仓频率要求。没有同时满足者，就明确判定本轮模型不够好，不继续偷偷放宽标准。

### 必须报告的结果

除账户收益、波动、回撤外，至少报告：每季度收益；实际交易回合胜率及平均盈亏；未平仓损益；实际持仓频率；成交失败率；各仓位约束的生效时间；预测概率分桶表现。

胜率不只给一个百分数，还要给交易数量、时间分布和按时间块重采样的不确定性区间，避免把同一市场行情中的高度相关交易当成大量独立证据。

收益计算则必须从扣费账户净值出发：

$$
CAGR=
\left(
\frac{NAV_{\text{end}}}{NAV_{\text{start}}}
\right)^{1/\text{实际年数}}-1
$$

Qlib当前 `risk_analysis` 默认仍是加法累计，虽已支持 `mode="product"`，也需要显式核对年化尺度；不能把默认输出或超额收益分析直接当作25%账户复合年化的证明。

预测、参数、模型、每日持仓和新增审计表都可以继续保存到Qlib的 `R`/Recorder，不需要另搭实验平台。([Qlib Documentation][3])

## 最后的设计结论

**我建议你将旧版改成这套V2，而不是继续微调旧版的均线、ATR和市场阈值。**

核心变化只有三件：

**第一，从“满足一种漂亮形态才买”，改成“按真实交易政策，预期收益和盈利概率同时合格才买”。**

**第二，从多个机制不断压仓，改成统一的市场上限与组合风险预算，并明确空仓后的恢复条件。风险验收不变。**

**第三，从最后看一条净值曲线，改成先验证收益信号，再逐层检查胜率、市场控制和波动约束的贡献；最低持仓频率从第一轮就参与淘汰。**

这版尚不能被称为“已经提高收益的策略”。它是一个**针对旧版可确认缺陷、且能够用回测证伪的新设计**。下一次回测不仅要回答赚了多少，还必须能明确区分：究竟是没有选股收益、胜率门槛太耗机会、市场控制无效，还是执行与数据出了问题。这样才不会再次拿到“收益很差”四个字，却只能靠事后叙事猜原因。
