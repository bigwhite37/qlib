我建议把第一版设计成：

> **“市场状态约束的低波趋势回撤策略”：在全市场寻找已经形成上升趋势、波动相对温和、近期出现适度回撤且开始修复的个股；市场强时提高仓位，市场弱时降低仓位，极端风险时空仓。**

它不是“买波动最低的股票”，也不是“每天无条件买模型排名最前的股票”。**收益来源是趋势中的回撤修复；低波动来自选股、分散和仓位控制；高胜率来自入场筛选，而不是长期拖着亏损仓位不卖。**

以下依据我实际读取的 Qlib 主分支快照 `79633dd9506ea689e5400dea0197717b5b3d74b7` 设计。**这次核对了源码，但没有读取你的本地行情，也没有运行回测；因此，下文的数值是待验证的策略初始参数，不是已经实现的业绩。**

## 一、先把目标写成可验收的合同

你的“低波动、稳定盈利、高胜率”需要具体量化，否则很容易得到一条看起来不错、实际上不符合要求的曲线。

我建议第一版采用下面这套研究验收标准：

| 项目 | 第一版标准 |
|---|---|
| 收益目标 | **样本外扣费后账户复合年化收益 ≥25%** |
| 年化波动率 | **≤10%** |
| 最大回撤 | **≤10%，争取≤8%** |
| 交易胜率 | **完整交易回合扣费后胜率 ≥70%** |
| 稳定性 | 单独严格检查：**每个完整自然季度账户净收益 >0** |
| 最低有效持仓频率 | **任意完整滚动252个交易日，至少60%的交易日满足有效持仓条件** |
| 防止局部长时间休眠 | **任意完整滚动63个交易日，至少40%的交易日满足有效持仓条件** |
| 有效持仓条件 | **实际股票市值占净资产≥20%，且至少持有3只股票** |
| 交易方向 | 只做多、不融资、不使用衍生品；可以持有现金 |

这里有三个口径需要固定。

**第一，25%是账户收益，不是持仓股票收益，也不是相对沪深300的超额收益。** 空仓时间、闲置资金、交易成本都要计入。

**第二，70%胜率按完整交易回合计算。** 同一股票从首次建仓到全部退出算一回合；中途减仓不能拆成多个“盈利交易”抬高胜率。期末未平仓股票仍按市价计入账户净值，并单列浮亏和持仓年龄。

**第三，最低频率是硬验收约束。** 252日窗口至少需要152个有效持仓日，63日窗口至少需要26个。低于这个门槛，策略就是不符合需求，不能把门槛下调后再宣布通过。

这是一组很强的联合目标。研究任务不是预先认定它们一定能够同时实现，而是用固定规则和封存数据验证；**收益达标但频率、回撤或胜率不达标，都不能算成功。**

## 二、交易信息边界：前一日决策，下一日收盘尝试成交

### 1. 固定时序

整个系统只采用下面这一条时序：

```text
T日收盘后
  获取截至T日的日线
  计算市场状态、股票信号、风险和仓位
  冻结T+1日的股票名单、买卖方向、委托数量和价格约束
          ↓
T+1日收盘
  根据成交条件撮合
  可能成交、部分成交或不成交
          ↓
T+1日收盘后
  更新账户和持仓状态
  生成T+2日决策
```

**不能使用 T+1 日的收盘、最高、最低、全天成交量来挑选 T+1 日要买的股票。** 这些信息只能由撮合和结算模块使用。

同样，不能先看到 T+1 日收盘价，再反推出“刚好买到目标仓位”的股数。

这是需要特别修改 Qlib 默认行为的地方：`TopkDropoutStrategy` 虽然读取上一交易步的信号，但买入数量会使用成交日的 `get_deal_price()` 计算；它也不是一个能够按目标总仓位全面减仓的完整实现。

### 2. 买入价格约束

为了避免“昨天出现回撤信号，今天已经大幅拉升，仍然照单买入”，第一版规定：

> **买入最高接受价格 = T日原始收盘价 ×1.03。**

委托数量按这个最高接受价格、可用现金、费用和交易单位预先计算。

T+1 日收盘价高于该价格，订单不成交。**不能因为原定股票没买到，事后改买当天另一只表现更好的股票。**

卖出也应采用预先确定的合法委托条件，而不是假设任何风险卖单都能无条件按收盘价成交。

### 3. 不预支同一收盘撮合中的卖出资金

买单预算只使用决策时已经可用的现金，不依赖同一收盘撮合中尚未完成的卖出回款。

Qlib 的执行器提供 `settle_type`，持仓实现中也有 `ST_CASH="cash"` 和延迟现金处理，可以复用这套机制，并增加现金预算断言。这里是本策略的保守执行约定，不是把它解释为“A股卖出资金依法次日才能买股票”。

## 三、股票池：面向历史全市场，不使用今天的股票名单回看过去

### 1. 基础范围

使用 `D.instruments("all")` 对应的数据，但必须核实它实际包含哪些证券、哪些历史区间。

策略范围应当是：

> **在当时已经存在、并且在你的数据中有有效历史记录的全部A股个股中筛选。**

不限制为沪深300、中证500，也不预先固定几个行业。但是，**`all` 这个名称不能证明你的数据真的覆盖全部A股、退市股票以及北交所股票。** Qlib 的股票池本质上是“股票名单及其有效日期区间”，实际覆盖仍取决于数据包。

### 2. 可买股票的基础过滤

第一版固定如下，不做大量寻优：

| 条件 | 初始规则 | 用途 |
|---|---|---|
| 历史长度 | 至少120个有效日线观测 | 保证趋势与风险指标可计算 |
| 近期交易连续性 | 最近20个交易日至少18日有有效行情 | 避免频繁停牌、数据残缺 |
| 原始价格 | 原始收盘价≥3元 | 排除低价和价格刻度影响较大的样本 |
| 流动性 | 最近20日成交额或经核验的成交额代理，位于全市场前80% | 排除最不活跃部分 |
| 波动 | 60日收益波动率不高于当日全市场70%分位数 | 排除最躁动的股票 |
| 数据质量 | 必需字段、复权因子、价格关系通过检查 | 防止异常数据进入策略 |

这里不要求买“波动最低的20%”。那样会把策略推向另一种资产风格。**本策略只排除过度波动，然后在剩余股票中找趋势机会。**

Qlib 日线价格和成交量存在复权、归一化约定；官方说明可以用 `$close / $factor` 恢复原始收盘价。因此，不能直接把 `$close >= 3` 当作三元股过滤，也不能未经核验就把调整后成交量当真实股数。

**ST、退市整理、行业、市值不是本方案默认已经拥有的数据字段。** 缺少历史状态时，不能声称“已经准确剔除历史ST”；缺少行业时，也不能声称“已经完成行业中性化”。

## 四、市场整体强弱：不仅决定是否买，还决定买多少

这一层直接使用个股日线汇总，不依赖额外宏观数据。

### 1. 构造三个市场指标

**市场趋势代理 \(M_t\)**

先计算当时基础市场样本的个股日收益率中位数，再累计成一条市场趋势代理曲线：

\[
r_t^M=\operatorname{median}_i(r_{i,t}),\qquad
M_t=M_{t-1}(1+r_t^M)
\]

样本资格使用此前已知信息确定，缺失情况单独统计。它只是判断市场状态的代理，**不是可直接投资的指数，也不作为策略的收益基准**。

**市场宽度 \(B_{60,t}\)**

\[
B_{60,t}
=
\frac{\#\{i:C_{i,t}>MA_{60,i,t}\}}
{\#\{\text{当日有效基础市场样本}\}}
\]

它回答：有多少股票站在自己的60日均线上。

同时计算 \(B_{20,t}\)，用于识别短期修复。

**下跌扩散 \(Q_t\)**

\[
Q_t=
\frac{\#\{i:r_{i,t}<-3\%\}}
{\#\{\text{当日有效基础市场样本}\}}
\]

它回答：下跌是否正在广泛扩散。

### 2. 四种市场状态

以下为初始固定参数，按“极端风险→强势→弱势→中性”的顺序判断：

| 状态 | 判断规则 | 股票总仓位上限 |
|---|---|---:|
| 极端风险 | 市场代理5日跌幅达到6%；或 \(B_{60}<20\%\) 且 \(Q>35\%\) | **0%** |
| 强势 | \(M>MA_{60}(M)\)，市场20日均线高于5日前，且 \(B_{60}\ge55\%\) | **90%** |
| 弱势 | \(M<MA_{60}(M)\)，且 \(B_{60}<40\%\) | **25%** |
| 中性 | 其余情况 | **55%** |

**恶化时立即按下一交易日执行降仓；改善时连续两个信号日确认后再提高仓位。**

弱势市场不是完全禁止交易，但新增仓位还要求：

\[
B_{20,t}-B_{20,t-5}\ge5\text{个百分点}
\]

也就是：**只有市场出现一定范围的修复，才允许用小仓位参与满足个股条件的机会。**

这样可以区别：

- 少数股票抗跌，但市场仍在持续恶化；
- 市场整体尚弱，但越来越多股票开始修复。

市场状态给出的是**上限，不是必须用满的目标**。没有合格股票时，实际仓位可以更低。

## 五、策略本身：买“趋势中的适度回撤修复”

这是整个方案的核心，而不是工程配套。

### 1. 入场条件

股票通过基础过滤后，还必须同时满足以下四组条件：

| 条件组 | 具体规则 |
|---|---|
| 中期趋势仍然向上 | 收盘价高于60日均线；20日均线高于60日均线；60日均线高于5日前 |
| 相对强势 | 60日相对市场收益，位于可买股票前30% |
| 回撤适中 | 当前收盘价距离最近20日最高收盘价，为 **1～3倍ATR20** |
| 修复开始 | 当日收盘高于前收盘，且重新站上5日均线；当日涨幅不超过4% |

这里的 ATR20 是过去20日真实波幅的均值，用来衡量该股票自身正常的价格摆动范围。

这组条件的含义是：

> **股票原本强于市场，趋势尚未破坏；最近回撤了，但没有严重破位；现在出现初步修复，不过尚未变成明显追涨。**

不买三类股票：单纯因为跌得多而显得便宜的股票；趋势已经破坏但波动看起来变小的股票；刚刚大幅拉升、已经失去回撤买入价格优势的股票。

这些都是**研究假设**，需要样本外验证；不能把技术条件本身当成盈利证据。

### 2. 候选股票排序

规则基线先不用机器学习，采用一个简单、可解释的分数：

\[
S_i
=
0.50\,Rank(RS_{60,i})
+
0.25\,Rank(TrendQuality_{60,i})
+
0.25\,Rank(-DownVol_{20,i})
\]

其中：

- \(RS_{60}\)：60日个股收益减去市场代理收益。
- \(TrendQuality_{60}\)：过去60日净上涨幅度相对于累计价格摆动的比例，偏好走得较顺的趋势。
- \(DownVol_{20}\)：过去20日下行波动，偏好回撤较温和的股票。

`Rank` 在这里是**同一天的横截面百分位排名**，不是对一只股票做时间序列排名。

价格均线、收益、波动、滚动极值等计算可使用 Qlib 表达式引擎；市场聚合和横截面排序再用少量 Pandas 处理，不需要另建因子平台。Qlib 原生支持通过 `QlibDataLoader` 定义公式化特征。

### 3. 建仓方式

第一版采用：

| 项目 | 初始设置 |
|---|---|
| 最大持股数 | **12只** |
| 单股目标仓位上限 | **净资产的8%** |
| 单次计划止损风险 | **净资产的0.4%以内** |
| 每日普通新增股票 | **最多2只** |
| 权重分配 | 以逆波动权重为基础，再施加单股及风险上限 |
| 高相关股票 | 最近60日收益相关系数超过0.80时，优先保留分数更高者 |
| 候选不足 | 留现金，不降低入场标准凑满持仓 |

相关性约束只能减少“看起来买了很多只，实际上走势高度一致”的情况，**不能替代行业风险控制**。

为避免亏损加仓，第一版规定：**不因股价下跌而补仓摊低成本；持有期间允许风险减仓，但不自动补回原权重。**

## 六、持有和退出：不能靠拖延认亏制造高胜率

### 1. 四类退出规则

所有退出信号都是收盘后生成，下一交易日收盘尝试执行。

| 退出类型 | 初始规则 |
|---|---|
| 个股止损 | 入场时确定止损幅度：`clip(2.5×ATR20/价格, 4%, 8%)`；收盘触发后下一日卖出 |
| 趋势失效 | 收盘跌破60日均线；或连续两个收盘低于20日均线 |
| 盈利保护 | 浮盈达到2倍入场ATR后，启用“最高收盘价回撤1.5倍入场ATR”的跟踪退出 |
| 时间退出 | 最长持有20个交易日，届时退出，不因为仍亏损而无限延长 |

此外，普通排名退出可以规定为：**至少持有3日后，连续两日跌出基础可买股票综合评分前50%，退出。**

但止损、趋势失效、市场降仓不受这3日限制。

**4%～8%是止损信号阈值，不是实际最大亏损保证。** 下一日价格跳变、停牌、跌停或成交失败，都会使实际损失超过阈值。

### 2. 账户级风险控制

市场仓位上限之外，再加两层限制。

**目标波动率控制：**

\[
g_{\text{vol}}
=
\min\left(1,\frac{10\%}{\widehat{\sigma}_{portfolio}}\right)
\]

用截至信号日的过去60日收益，估计候选组合的年化波动率。

可以复用 Qlib 的 `ShrinkCovEstimator`，例如固定 `alpha=0.3`、`target="const_corr"`，避免直接用短样本协方差做过于激进的风险估计。传入小数形式的收益时，要明确设置 `is_price=False`、`scale_return=False`，否则其默认百分数缩放会改变风险量纲。

**账户回撤限制：**

| 账户相对历史最高净值的回撤 | 总仓位额外上限 |
|---|---:|
| 小于4% | 不额外限制 |
| 达到4% | 50% |
| 达到6% | 25% |

最终：

\[
g_t
=
\min\left(
g_{\text{market}},
g_{\text{vol}},
g_{\text{drawdown}},
95\%
\right)
\]

再经过候选不足、单股上限、现金预算和交易单位约束，得到实际订单。

这里不使用“回撤达到某个数就永远空仓，等净值恢复再开仓”的规则，因为全现金净值本身通常不会恢复。**回撤控制负责降低风险；市场极端状态负责允许完全退出。**

## 七、最低持仓频率怎样落地

不能只设置“每年交易至少几次”。少量仓位频繁买卖，仍然可能大部分时间没有真正参与市场。

定义每日有效持仓：

\[
I_t=
\mathbf{1}
\left(
\frac{\text{股票市值}_t}{\text{净资产}_t}\ge20\%
\ \land\
\text{持股数量}_t\ge3
\right)
\]

然后计算：

\[
F_{252,t}=\frac{1}{252}\sum_{k=0}^{251}I_{t-k}
\]

\[
F_{63,t}=\frac{1}{63}\sum_{k=0}^{62}I_{t-k}
\]

要求分别不低于60%和40%。

**计算必须使用每日实际成交后的持仓，而不是计划仓位。** 买单没成交、风险降仓、停牌导致的仓位偏离，都要真实反映。

我的设计选择是：

> **把频率作为整套策略的硬可行性条件，而不是单笔订单“凑数”的理由。**

也就是说，开发中一旦发现这套规则只能做到40%的长期有效持仓频率，就判定它不符合需求；不能给它加一条“频率不足时随便买几只”的补丁。

实盘监控同样记录频率违规，不能静默豁免。但外部成交条件不可控，因此不能承诺未来任何情况下都绝不突破频率下限。**发生冲突时不强行制造危险头寸，同时明确标记策略已经不达标。**

这个区别很重要：它既保留你的硬要求，也避免用高风险交易掩盖策略覆盖机会不足的问题。

## 八、机器学习增强：只增加一个小模型，不替代整套交易规则

我建议按两个版本推进：

**V0：上述纯规则策略。**
先验证趋势回撤这个收益来源、市场仓位控制和执行真实性。

**V1：在V0候选池内增加一个 LightGBM 模型。**
模型只帮助筛选和排序，不直接决定全部仓位，也不能绕过市场风险和止损规则。

Qlib 自带 `LGBModel`，支持 `mse` 和 `binary` 两种目标；这里可以直接复用二分类版本。

### 1. 模型预测什么

预测：

> **以T+1日收盘买入，持有10个交易日后，价格收益是否超过0.5%。**

连续收益标签为：

```python
Ref($close, -11) / Ref($close, -1) - 1
```

再转换为二分类标签：

\[
y_t=\mathbf{1}(R_{t+1\rightarrow t+11}>0.5\%)
\]

0.5%只是第一版设置的交易摩擦缓冲门槛，并不意味着每笔订单的实际成本都恰好如此。

尾部没有未来价格、或者标签区间价格缺失的样本，标签必须保持缺失并从训练中移除，**不能把缺失标签转换成0类**。

这个模型预测的是固定10日结果，**不是实际止盈止损后的完整回合胜率**。最终70%胜率仍必须由真实回测成交记录计算。

### 2. 使用什么特征

使用 Qlib 的 Alpha158 特征族，加上前述市场趋势、市场宽度和下跌扩散指标。

但不能原样复制默认配置：当前 `Alpha158` 默认特征包含 VWAP，默认学习处理还会对标签进行横截面标准化。你的数据缺少 VWAP 时应移除相应特征；使用0/1分类标签时，必须取消标签标准化，只保留必要的缺失标签过滤。

### 3. 第一版模型配置与用途

采用小模型即可：`loss="binary"`、`num_leaves=15`、`max_depth=4`、`learning_rate=0.03`，最多500轮，50轮早停，固定随机种子。

初始使用方式：

\[
S_i^{V1}=0.5S_i^{V0}+0.5Rank(p_i)
\]

并将 `p_i≥0.60` 作为待验证的候选门槛。模型输出需要在验证集检查分桶命中率和校准情况，不能把0.60直接宣称为真实60%的成功概率。

**只有V1在滚动验证中同时改善扣费收益或风险，并且没有破坏持仓频率，才进入封存测试。** 否则保留V0，不因为“用了机器学习”就优先选V1。

## 九、2015—2026年的数据应该怎样划分

我建议分成五段。

表中使用自然日期边界；实际读取和交易日期统一由 `D.calendar` 映射，不假设1月1日就是交易日。

| 区间 | 定位 | 可以做什么 | 不可以做什么 |
|---|---|---|---|
| **2015-01-05～2015-12-31** | 数据审计、指标预热、补充压力回放 | 检查复权、股票池、缺失、成交规则；有足够历史后做补充回放 | 将预热不足的结果当完整年度业绩 |
| **2016-01-01～2019-12-31** | 机制开发区 | 定义规则、构造标签、训练初始模型、排查实现问题 | 把这里的好结果当样本外证据 |
| **2020-01-01～2022-12-31** | 滚动验证区 | 比较V0/V1，选择少量参数，决定是否采用模型 | 无限调参，直到各年都漂亮 |
| **2023-01-01～2024-12-31** | 第一封存样本外区 | 对冻结方案做一次完整检验 | 看完结果后微调，再把它称为未见数据 |
| **2025-01-01～2026-09-14** | 最终封存、近期样本外区 | 最后检验近期适应性、交易成本、频率和风险 | 用来修复前面暴露的问题，再报告为独立验证 |

### 为什么2015年不是直接丢掉

因为数据起点就是2015-01-05，最初没有足够历史计算120日资格及各类滚动指标。

因此，2015年首先承担预热和审计用途；具备足够历史后的区间仍需做补充压力回放，并保留损失和失败记录，**不能因为它不进入完整年度比较就忽略它。**

### 为什么需要两段封存数据

第一段检查策略在较长的未参与设计的数据中是否有效；第二段检查它在最近的数据中是否仍然有效。

建议最终报告分别列出：

- 2023—2024年样本外结果。
- 2025—2026-09-14最终封存结果。
- 2023—2026-09-14连续样本外结果。

其中，**25%的目标至少要求连续样本外整体和最终封存段分别达到**，不要求每一个自然年都达到25%。每个完整自然季度正收益则作为另一项独立的严格检查。

2026年第三季度截至9月14日尚未结束，不能算作一个完整季度；2026年结果也不能只给一个年化数字，必须同时报告年初至今收益。

## 十、滚动训练怎么做，怎样防止偷看未来

### 1. 固定更新制度

V1采用：

> **每个自然季度开始前训练一次；此前3年训练，此前最近1年验证，预测接下来1个季度。**

例如：

| 预测区间 | 训练区间 | 模型内部验证区间 |
|---|---|---|
| 2020年第一季度 | 2016—2018年 | 2019年 |
| 2023年第一季度 | 2019—2021年 | 2022年 |
| 2025年第一季度 | 2021—2023年 | 2024年 |
| 2026年第三季度 | 2022-07～2025-06 | 2025-07～2026-06 |

这是滚动模型的固定更新协议，不是根据近期亏损随时更换策略参数。

**封存期间允许按照预先确定的协议，用已经发生、标签已经成熟的数据重新训练。** 不允许研究人员看到封存收益后再调整特征、阈值、市场状态规则或更新周期。

### 2. 两个边界都要清除标签穿越

标签使用到了 \(T+11\) 的价格，因此训练和验证边界不能只按特征日期切分。

必须满足：

```text
训练样本的 label_end_time < 验证区间开始时间
验证样本的 label_end_time < 预测区间开始时间
所有参与拟合的标签，在该次训练时已经完整可见
```

Qlib 有 `RollingGen` 和 `trunc_days`。不过，当前实现的截断主要围绕测试起点处理，不能因此假定训练—验证边界也自动完全隔离；这一处需要补显式检查。原生 `step` 按交易日数滚动，也不等于自然季度，因此本方案用一个小函数根据交易日历构造季度任务，其他任务结构继续复用 Qlib。

### 3. 拼信号，不拼“重置后的漂亮收益”

各季度只输出当时模型生成的样本外信号，最后拼成连续信号序列。

再用同一个账户连续回测：

> **换季度不清仓，换年份不重置本金，也不重置历史最高净值。**

否则持仓跨期、回撤和现金约束会被人为改变。

此外，若你已经根据2023—2026年的这份数据调过类似规则，就应将相应区间标记为“已接触历史检验”；真正未见数据只能来自此后新增的数据，不能重新贴一个“封存”标签解决污染。

## 十一、哪些直接用Qlib，哪些必须自己补

### 1. 最大化复用的实现结构

| 功能 | 使用Qlib的部分 | 需要补的内容 |
|---|---|---|
| 日历、证券范围、行情读取 | `D.calendar`、`D.instruments`、`D.features` | 覆盖审计、历史样本资格 |
| 公式特征 | `QlibDataLoader`、表达式引擎 | 市场聚合、横截面排序 |
| 数据集与处理 | `DataHandlerLP`、`DatasetH`、Alpha158特征族 | 市场特征拼接、分类标签处理 |
| 模型 | `LGBModel` | 无须另写模型框架 |
| 风险估计 | `ShrinkCovEstimator` | 仓位缩放和风险上限 |
| 策略 | `WeightStrategyBase` | 入场、持有、退出、目标仓位 |
| 订单 | `OrderGenerator`扩展点 | 严格前一日定数量、价格约束、现金预算 |
| 撮合和账户 | `Exchange`、`SimulatorExecutor` | A股规则适配和限制性撮合 |
| 实验与记录 | `qrun`、`R`、`SignalRecord`、`PortAnaRecord` | 自定义验收指标与审计表 |

`WeightStrategyBase` 已经提供从目标权重到订单生成的连接，是比直接修改Topk策略更合适的起点。

工程上保持一个独立Python项目即可，不修改Qlib上游，不引入强化学习、复杂模型集成、在线参数自适应或多策略资金分配器。

### 2. 不能直接复用的三个默认行为

**默认Topk策略不能承担这套目标仓位语义。**
它主要管理排名和股票替换，并会使用成交日价格计算新买股数，不能仅设置一个 `risk_degree` 就认为已经实现全面动态降仓。

**`OrderGenWOInteract` 也需要检查和收紧。**
它虽然主要使用预测日收盘价估算数量，但当前源码仍查询成交日的可交易状态。严格实现中，应把这类未来状态检查移到执行层，让策略只生成事前订单。

**不要用默认报告中的收益指标直接验收25%。**
`PortAnaRecord` 默认重点分析相对基准的超额收益；`risk_analysis` 默认采用加法累计。当前源码已经支持 `mode="product"`，可以复用，但仍需明确年化尺度，并用账户净值交叉校验。

主验收采用账户净值计算：

\[
CAGR=
\left(\frac{NAV_{\text{end}}}{NAV_{\text{start}}}\right)^{1/\text{实际年数}}-1
\]

最大回撤也从包含初始净值的账户曲线计算，不能用“累计超额收益的回撤”替代。

## 十二、只有日线时，必须保留哪些执行限制

### 1. 收盘成交不等于保证成交

Qlib 的 `Exchange` 支持收盘价格、方向性交易限制、成交量上限、手续费和冲击成本接口，可以复用这些能力。

但是，日线没有收盘时点的对手盘和排队信息。

第一版应同时约束：

- 委托数量不超过此前20日平均成交量的一个小比例。
- 模拟成交数量不超过成交日全天成交量的一个小比例。
- 停牌、价格条件不满足、疑似封板等情况可以不成交。

例如先采用 **0.05%的成交量参与率上限**，并做更严格的压力测试。这里的全天成交量只是容量约束代理，不能证明收盘时一定有足够流动性。

### 2. 历史交易规则必须按日期处理

不能对2015—2026年的全市场统一写一个 `limit_threshold=0.095` 就结束。

交易制度、板块涨跌幅限制和历史风险警示状态都需要区分；例如沪深主板风险警示股票的涨跌幅规则在2026年7月发生过变化。

**在不增加外部行情和基本面数据的前提下**，可以将公开交易制度作为按日期生效的静态规则配置；但历史ST身份等无法从现有日线准确恢复的部分，必须标记为未知。

对于未知状态，另做更保守的方向性限制撮合，例如在接近较小涨跌幅阈值时禁止相应方向成交。它会误拒部分实际可成交订单，因此只能称为**保守敏感性检验**，不能称为精确重建。

### 3. 费用要匹配本金规模

不要沿用官方示例中很大的默认账户规模，掩盖小资金下的最低佣金和交易单位影响。

建议初始研究本金设为**10万元测试单位**，同时检查30万元、100万元规模；这只是策略容量测试，不是在假设你的实际投入。

费用拆分为：

\[
\text{成本}
=
\text{佣金及最低佣金}
+
\text{卖出税费}
+
\text{其他规费}
+
\text{执行摩擦附加成本}
\]

印花税要使用历史生效日期，不能把2023年8月28日以后减半征收的规则套用到全部历史。

为保持“按收盘价成交”的研究口径，成交价仍记收盘价，执行摩擦可以单独扣为成本。先测试每边10个基点附加成本，再提高到20、30个基点。

复权数据能支持价格收益研究，但未必足以完整重建分红现金到账、红利税和公司行动后的真实账户。**数据无法支持的部分要披露，不能把它包装成完全精确的券商税后现金回放。**

## 十三、回测最后必须交付什么

Qlib 可以保存信号、标签、日度组合报告、每日持仓、执行指标，并通过 `R` 保存参数、模型和自定义结果；不需要自己再建一套实验管理平台。

在此基础上，额外保存四类审计数据就足够：

| 数据 | 必须能够回答的问题 |
|---|---|
| 每日决策表 | 当时市场是什么状态？为何选这只股票？为何是这个仓位？ |
| 委托与成交表 | 哪些订单未成交？是否使用了未来价格定数量？现金是否足够？ |
| 完整交易回合表 | 实际赚亏多少？持有多久？什么原因退出？ |
| 账户约束表 | 波动、回撤、实际仓位、63日和252日有效持仓频率是否合格？ |

验收顺序固定为：

**先检查因果时序和数据问题，再检查频率、波动、回撤、胜率及季度稳定性，最后判断是否达到25%年化。**

至少比较三套方案：固定仓位的规则基线、加入市场状态与风险控制的V0、再加入LightGBM的V1。它们必须使用同一套严格执行条件，才能分辨提升来自真实选股能力，还是仅仅来自更乐观的成交假设。

开发阶段最多比较少量预先登记的配置，例如不超过12组。封存阶段只测试冻结的最终方案，同时执行成本提高、买卖延迟、成交更保守等压力测试。**不能在封存段失败后不断增加参数，直到重新达到25%。**

## 最终建议

第一版就落地这一条主线：

> **全市场历史股票池 → 过滤过度波动和低流动性 → 找上升趋势中的适度回撤修复 → 最多12只分散持有 → 市场四状态控制仓位 → 目标波动及回撤降仓 → 前一日冻结订单、下一日收盘尝试成交 → 严格检查实际持仓频率。**

先跑可解释的V0，再决定是否采用Qlib自带LightGBM增强。**不要一开始就用复杂模型追逐25%，也不要靠长期空仓或拖延止损制造“低波、高胜率”。**

这份设计最关键的交付标准是：**在冻结规则、真实扣费和连续样本外账户下，25%年化、低波动、高胜率与最低持仓频率必须同时成立。只满足其中一部分，就明确报告差在哪一项，而不是改口径宣布成功。**
