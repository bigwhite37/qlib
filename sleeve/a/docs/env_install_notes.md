# Installing this qlib checkout into the conda environments

Recorded 2026-09-16. This repository is `/Users/shuzhenyi/code/python/qlib`
(distribution name `pyqlib`, version generated by setuptools-scm).

## What was done

```bash
cd /Users/shuzhenyi/code/python/qlib
SLEEVE_PYTHON=/Users/shuzhenyi/miniconda3/envs/py310/bin/python scripts/run_python_3gb.sh -m pip install -e . --no-deps
SLEEVE_PYTHON=/Users/shuzhenyi/miniconda3/envs/qlib/bin/python  scripts/run_python_3gb.sh -m pip install -e . --no-deps
```

`--no-deps` is deliberate: both environments already have every runtime
dependency (numpy, pandas, scipy, lightgbm, scikit-learn, duckdb, mlflow, ...),
and omitting it would let pip upgrade numpy/pandas inside them.

Build isolation is left **on** so the Cython extensions are compiled against
numpy >= 2 headers. That matters because the two Python 3.10 environments have
different numpy versions (py310 has 1.26.4, qlib has 2.2.6) and they **share the
same compiled files** in the source tree
(`qlib/data/_libs/{rolling,expanding}.cpython-310-darwin.so`, which are
git-ignored). Binaries built against numpy 2 headers load under both; binaries
built against numpy 1.x would fail under numpy 2.

## The py310 name clash (why one directory was moved aside)

`py310` also contained an unrelated local distribution named `qlib`
(version 0.0.2.dev20, "A Q Library for Data Scientist" —
`qadapter.py`, `qfacade.py`, `qlibbase.py`, `manual_decline/`, and **no
`__init__.py`**). Because it owns the same top-level name, `import qlib` in that
environment resolved to a namespace package and the checkout's
`qlib/__init__.py` never loaded, so `qlib.__version__` and `qlib.init` were
missing even though `qlib.data.*` resolved correctly.

It was moved aside — reversibly, nothing deleted:

```
/Users/shuzhenyi/miniconda3/envs/py310/lib/python3.10/site-packages/qlib
  -> .../site-packages/_qlib_local_0.0.2.dev20.moved_aside
```

To put it back (and re-break the py310 qlib import), rename it back:

```bash
SP=/Users/shuzhenyi/miniconda3/envs/py310/lib/python3.10/site-packages
mv "$SP/_qlib_local_0.0.2.dev20.moved_aside" "$SP/qlib"
```

Its `qlib-0.0.2.dev20.dist-info` was left in place, so `pip list` still reports
it; only the importable directory was renamed.
